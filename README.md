# Сушкевич Бот

Backend для Telegram-бота «Сушкевич Бот»: клинически ориентированный диалог,
память пользователя и mini-app профиля поддержки.

Главная роль бота — не заменять врача и не ставить диагнозы по переписке, а помогать
пользователю психиатрически сориентироваться: описать состояние, заметить динамику,
распознать красные флаги, оценить срочность, собрать материал для специалиста и выбрать
безопасный следующий шаг.

Бот мыслит не отдельными симптомами и не простыми совпадениями слов, а клиническими
гипотезами, уровнем риска, синдромами, динамикой во времени, сохранностью критики,
социальным функционированием, соматикой, ПАВ и лекарствами.

## Основные части

- `app/services/dialogue.py` — основной диалог, системный промпт, кризисная логика,
  контакт врача, выбор контекста памяти и клинической базы.
- `app/services/clinical_knowledge.py` — retrieval по клиническим знаниям: читает Markdown,
  кэширует файлы, режет по разделам и подставляет только релевантные фрагменты.
- `app/services/diagnostic_domains.py` — осторожная маршрутизация по клиническим доменам:
  психоз/продром, мания, депрессия, РПП, самоповреждение, эмоциональная дисрегуляция,
  ПАВ и соматика. Это не диагнозатор.
- `app/services/memory.py` — извлечение и обновление долговременной памяти, профиля,
  лайфхаков и дневниковых инсайтов.
- `app/services/support_profile.py` — сборка mini-app профиля поддержки, метрики,
  лайфхаки, дневник, ограничения текста.
- `app/web/support.py` — HTML/CSS/JS mini-app профиля поддержки.
- `app/services/llm.py` — вызовы OpenRouter и извлечение JSON из ответов модели.

## Что сохраняется в базе

- `users` — Telegram-профиль, краткое описание пользователя, предпочтения поддержки,
  заметки о рисках.
- `sessions` — активные диалоги и краткие выводы по текущей беседе.
- `messages` — история сообщений пользователя и бота.
- `user_memories` — долговременная память: важные факты, повторяющиеся ситуации,
  выводы пользователя, цели, риски, предпочтительный стиль поддержки и стратегии,
  которые уже помогали.
- `important_facts` — структурные факты: имя, работа, отношения, триггеры,
  предпочтения, границы и другие вещи, которые лучше помнить точно.
- `known_people` — важные люди из жизни пользователя: имя, роль, контекст отношений,
  эмоциональная окраска.
- `open_topics` — незавершенные темы, к которым бот может бережно вернуться позже.

Пользователь может управлять памятью обычным текстом: `запомни ...`, `забудь ...`,
`говори короче`, `будь мягче`, `давай на ты`, `по шагам`, `без списков`.

## Настройка поведения бота

Поведение можно менять без переписывания кода через переменные окружения:

- `CLINICAL_KNOWLEDGE_PATH` — путь к основному клиническому ориентиру бота.
- `CLINICAL_KNOWLEDGE_MAX_CHARS` — максимальный объем релевантной выборки из этой базы,
  который попадет в один запрос к нейросети.
- `MEMORY_EXTRACTION_ENABLED` — включает или выключает извлечение долговременной памяти.

Бот не ставит диагнозы как факт, не назначает и не отменяет лекарства. В опасных ситуациях
он продолжает помогать и коротко рекомендует связаться с врачом или экстренной помощью.
Конкретный контакт врача добавляется только при прямой просьбе пользователя или при сочетании
прямой просьбы о помощи с непосредственной опасностью для жизни.

## Клиническая база

Основной ориентир лежит в `app/knowledge/clinical_orientation.md`. Его не нужно ужимать:
код сам режет Markdown по разделам, кэширует файл и подставляет в запрос только релевантные
фрагменты. Дополнительные доменные карточки лежат в `app/knowledge/disorders/` и помогают
подбирать нужные разделы по сочетаниям признаков: психоз/продром, мания, депрессия,
РПП, самоповреждение, эмоциональная дисрегуляция, ПАВ и соматика.

Доменные маркеры используются только для выбора знаний и уточняющих вопросов. Они не являются
диагностикой и не заставляют бота ставить диагноз по совпадению слов.

Файлы базы:

- `app/knowledge/clinical_orientation.md` — главный расширенный ориентир: философия бота,
  клиническое мышление, красные флаги, диагностические оси, подростковая психиатрия,
  РПП, ПАВ, психофармакология и шаблоны ответов.
- `app/knowledge/psychiatry_literature_digest.md` — резервный placeholder под будущую
  выжимку литературы; пока не используется как основной источник.
- `app/knowledge/disorders/*.md` — короткие навигационные карточки по доменам. Они нужны,
  чтобы retrieval быстрее вытаскивал релевантные знания, не заменяя большой ориентир.

Если добавляется новый клинический домен, обычно нужно:

1. Добавить Markdown-карточку в `app/knowledge/disorders/` с frontmatter `domain` и `tags`.
2. Добавить домен, маркеры и `question_focus` в `app/services/diagnostic_domains.py`.
3. Добавить тест в `tests/test_clinical_knowledge.py`, чтобы проверить выбор домена и
   релевантного источника.

## Безопасность и контакт врача

Кризисная логика разделяет две ситуации:

- если есть опасность для жизни, бот добавляет короткую рекомендацию связаться с врачом
  или экстренной помощью, без конкретного контакта;
- если пользователь прямо просит контакт врача или пишет, что ему нужна помощь, и сообщение
  одновременно содержит кризисные маркеры, сервис добавляет контакт Сушкевича Антона
  Геннадьевича.

Сама модель в системном промпте просится не предлагать конкретные контакты самостоятельно:
контакт добавляет код в `ensure_risk_contact`, чтобы это происходило редко и по делу.

## Mini-app профиля

Mini-app доступен по `/app/support`. Он показывает:

- краткий профиль и метрики;
- персональные лайфхаки;
- дневниковые инсайты;
- ручные заметки пользователя.

Лайфхаки ограничиваются по размеру на backend и frontend, чтобы текст помещался в карточку
и не обрывался на полуслове. Поле создания нового лайфхака намеренно без placeholder.

## Локальный запуск

```bash
cp .env.example .env
docker compose up -d db
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload
```

API будет доступен по адресу:

```text
http://localhost:8000/docs
```

Mini-app профиля поддержки будет доступна по адресу:

```text
http://localhost:8000/app/support
```

Проверка:

```bash
curl http://localhost:8000/health
```

Тестовый запрос без Telegram:

```bash
curl -X POST http://localhost:8000/api/v1/messages \
  -H "Content-Type: application/json" \
  -d '{"telegram_id":123,"first_name":"Антон","text":"Мне тревожно, не могу уснуть"}'
```

## Переменные окружения

```env
APP_NAME=Сушкевич Бот
APP_ENV=production
API_V1_PREFIX=/api/v1
PUBLIC_BASE_URL=https://${{RAILWAY_PUBLIC_DOMAIN}}
PUBLIC_WEBAPP_URL=https://${{RAILWAY_PUBLIC_DOMAIN}}/app/support

DATABASE_URL=${{Postgres.DATABASE_URL}}

OPENROUTER_API_KEY=...
OPENROUTER_MODEL=openai/gpt-oss-120b:free
TELEGRAM_BOT_TOKEN=...
TELEGRAM_WEBHOOK_SECRET_TOKEN=long-random-string

CLINICAL_KNOWLEDGE_PATH=app/knowledge/clinical_orientation.md
CLINICAL_KNOWLEDGE_MAX_CHARS=5200
MEMORY_EXTRACTION_ENABLED=true
```

Старые переменные `PREFERRED_AUTHORS`, `AVOIDED_APPROACHES` и
`CUSTOM_CLINICAL_GUIDANCE` больше не используются и их можно удалить из Railway.

Если Railway даст обычный `postgresql://...`, код сам преобразует его в async/sync URL
для SQLAlchemy и Alembic.

## Railway

1. Создайте новый Railway project из GitHub-репозитория `medsi-children/suwkevich_bot`.
2. Добавьте сервис PostgreSQL.
3. В сервис backend добавьте переменные из блока выше.
4. В `PUBLIC_BASE_URL` укажите `https://${{RAILWAY_PUBLIC_DOMAIN}}` или полный публичный
   домен backend из Railway.
5. В `PUBLIC_WEBAPP_URL` укажите тот же домен со страницей mini-app:
   `https://${{RAILWAY_PUBLIC_DOMAIN}}/app/support`.
6. После deploy выполните в Railway shell:

```bash
python scripts/set_telegram_webhook.py
```

Webhook будет смотреть на:

```text
https://your-production-domain.up.railway.app/api/v1/telegram/direct-webhook
```

Кнопку меню Telegram mini-app можно настроить через BotFather. `PUBLIC_WEBAPP_URL` нужен
самому приложению и должен указывать на публичный HTTPS-адрес страницы `/app/support`.

Полезные официальные страницы Railway:

- PostgreSQL: https://docs.railway.com/databases/postgresql
- Dockerfile deploy: https://docs.railway.com/deploy/dockerfiles
- Variables: https://docs.railway.com/reference/variables
- GitHub autodeploy: https://docs.railway.com/deployments/github-autodeploys
